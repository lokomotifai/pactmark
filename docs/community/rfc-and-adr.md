---
title: RFC and ADR process
description: Record consequential product and architecture decisions before implementation drift.
---

> Compatibility: Pactmark 0.1.x.

Use an RFC for a change that needs community exploration: new public capability,
provider or platform contract, wire format, governance process, or significant
trade-off. State motivation, non-goals, security and compatibility impact,
alternatives, rollout, and evidence plan.

Use an ADR when the repository accepts an architecture decision. ADRs are immutable
records; supersede them with a new ADR instead of rewriting history. Update the
applicable release-readiness record when implementation evidence changes a fixed decision.
