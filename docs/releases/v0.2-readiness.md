## Candidate scope

The coordinated public release contains 18 `@pactmark/*` packages and the unscoped
`create-pactmark` initializer, all at version `0.2.0`. The private `@pactmark/executor-sh` workspace
remains version `0.1.0`, is excluded from public release artifacts, and is neither an npm
publication target nor a production-deployment claim.

The release incorporates the authority-boundary and independent security-audit remediation already
recorded in the historical [v0.1 readiness record](./v0.1-readiness.md): host-derived tool identity,
complete fail-closed policy preflight, bound grants and approvals, effect and executor admission,
HTTP and MCP boundary hardening, tenant-aware PostgreSQL and worker access, credential and telemetry
redaction, portable evidence attestations, safer initialization, packed-consumer strengthening, and
immutable supply-chain workflows.

## Version and publication invariants

- Every public package manifest and packed internal dependency must resolve to exact `0.2.0`.
- The protected workflow accepts only `publish-pactmark-0.2.0` on `main` in
  `lokomotifai/pactmark`.
- Candidate construction runs without npm publication authority. The separate `release` environment
  job re-verifies the frozen artifact before OIDC attestation and publication.
- All 19 npm trusted publishers must remain bound to repository `lokomotifai/pactmark`, workflow
  `release.yml`, environment `release`, and GitHub-hosted execution.
- No long-lived npm token is required or permitted by the release workflow.
- The annotated `v0.2.0` tag and immutable GitHub Release may be created only for the exact source
  commit whose registry-served tarballs pass anonymous checksum and provenance verification.
